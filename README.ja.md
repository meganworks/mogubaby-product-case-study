## 開発の背景｜日常的な育児課題をプロダクトへ

離乳食の開始後、保護者には「どの食材を試したか」「直近で何を食べたか」「市販ベビーフードに何が含まれるか」「保育施設の準備に必要な食材記録は揃っているか」といった管理負荷が発生します。

**食事の記録を単なる保存データで終わらせず、次の食材を選択する際に活用できないか。**

この一般的な課題を起点として、食材記録・履歴確認・保育施設向けの食材チェック等を支援するiOSアプリ「モグベビ」を企画・公開しました。

このリポジトリは、アプリの非公開ソースコードではなく、**課題の構造化、要件定義、AI活用型の実装・独立レビュー、品質改善、リリース判断**を説明する公開ポートフォリオです。

## プロダクト概要

| 項目 | 内容 |
| --- | --- |
| **プロダクト** | 離乳食・食材記録アプリ |
| **提供形態** | iOS・App Store公開 |
| **主な機能** | 食材記録、市販品検索、食材履歴、最終摂取記録・経過日数、並び替え、保育施設準備、成長記録 |
| **担当領域** | 課題設定、要求定義、UX・優先順位判断、品質受入、リリース承認 |
| **開発運用** | Claude Codeによる実装、ChatGPT/Codexによる別視点のレビュー、GitHub Issuesによる要件・判断履歴管理 |
| **公開実績** | 2026年10月にバージョン1.0.1を公開 |

## 4つのケーススタディ

### 01｜Customer Insight → Requirements

初期利用者のフィードバックを起点に、食材の「最後にいつ食べたか」を把握したいというニーズを、**最終摂取記録日・経過日数の表示と並び替え**に変換。献立自動作成などへ無制限に拡張せず、実装スコープを限定しました。

[課題発見と要件定義](./docs/ja/product-discovery.md)

### 02｜Requirements Management → Delivery

GitHub Issueを最新の仕様・優先順位・受入条件の参照先として管理。利用者の反応による方針変更も履歴を残して反映し、AIエージェントへの指示とレビュー結果を整合させました。

[要求管理とデリバリー統制](./docs/ja/delivery-governance.md)

### 03｜Independent AI Review → Quality

独立レビューにより、「他アプリから移行した初回摂取日」と「実際に確認できる直近の摂取日」が混同される境界ケースを検出。データの意味を明確化し、修正と回帰確認につなげました。

[品質改善ケーススタディ](./docs/ja/quality-management.md)

### 04｜Product Positioning → Release

「保育施設準備」中心の訴求から、**手軽な記録 → 日々の食材選択への活用 → 保育施設準備**へ優先順位を変更。App Store掲載クリエイティブと機能追加を同一リリースで整合させました。

[プロダクト戦略と公開](./docs/ja/product-and-launch.md)

## Human-in-the-loopのデリバリーモデル

```text
保護者に共通する課題・プロダクト仮説
               ↓
課題・優先順位・機能範囲の決定［Human］
               ↓
要件と意思決定の管理［GitHub Issues］
               ↓
実装・検証［Claude Code］
               ↓
独立した観点でのレビュー［ChatGPT / Codex］
               ↓
是正対応・回帰テスト［Claude Code］
               ↓
UX受入と公開最終承認［Human］
               ↓
App Store審査・公開
```

※ 実際に記録された役割分担の要約です。完全自律型AIや網羅的なテスト保証を意味しません。
