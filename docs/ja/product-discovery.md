## 課題｜食材チェックと食事の振り返り

既存の離乳食アプリは食材の摂取チェックに便利ですが、食事全体を日付単位で振り返りたい利用者には、操作導線や情報設計が適合しないことがあります。全利用者に共通する不満ではなく、詳細な食事管理を必要とする一部の保護者に着目しました。

| 利用場面 | 必要な情報・体験 |
| --- | --- |
| よく食べた料理を再現したい | 当日の献立や調理方法を振り返る |
| 食べやすい状態を把握したい | 硬さ・粒度・食事中の反応を記録したい |
| 食後に症状が現れた | 当日の食事内容や体調を確認したい |
| 次の食材を選びたい | 最終摂取記録日や経過日数を参照する |

設計上の重点は、日常的な入力負荷、操作の直感性、日付・食事単位の情報参照性です。上表は利用者のニーズを整理したもので、個々の記録項目がすべて専用機能として実装済みであることを示すものではありません。モグベビでは、食材記録、日記・カレンダー、摂取履歴を組み合わせています。

## ニーズを要件に変換

初期利用者の定性的なフィードバックから、食材の最終摂取履歴を可視化するニーズを把握しました。

| ユーザー課題 | 機能要件 |
| --- | --- |
| 前回の摂取日が不明 | 最終記録日・経過日数の表示 |
| 食材のローテーションが分かりにくい | 最終記録日による昇順・降順ソート |
| 食材を種類別に確認したい | 既存カテゴリ単位の操作性を維持 |
| 編集・削除・移行データが存在する | 記録の信頼性と日付の意味を定義 |
| 日々の操作負荷を下げたい | 大規模な献立提案機能ではなく、小規模改善を選択 |

**最終摂取日改善の対象外：** 自動献立生成、医学的な栄養評価、アレルギー予防効果の保証、在庫管理。

## 訴求できる能力

ユーザーの希望と、実装すべき最小機能を区別し、スコープを限定した点に価値があります。フィードバックは少数の定性的意見であり、栄養改善・利用継続率・ダウンロード増加などの成果を実証したものではありません。
