# Customer Discovery｜ユーザーニーズから機能要件へ

[ポートフォリオ](../../README.ja.md) ・ [English](../en/product-discovery.md)

## 課題

離乳食の記録が存在しても、「最後にその食材を食べたのはいつか」「しばらく記録していない食材は何か」を判断するには、履歴を手動確認する負荷が残ります。

## ニーズを要件に変換

初期利用者の定性的なフィードバックから、食材の最終摂取履歴を可視化するニーズを把握しました。

| ユーザー課題 | 機能要件 |
| --- | --- |
| 前回の摂取日が不明 | 最終記録日・経過日数の表示 |
| 食材のローテーションが分かりにくい | 最終記録日による昇順・降順ソート |
| 食材を種類別に確認したい | 既存カテゴリ単位の操作性を維持 |
| 編集・削除・移行データが存在する | 記録の信頼性と日付の意味を定義 |
| 日々の操作負荷を下げたい | 大規模な献立提案機能ではなく、小規模改善を選択 |

**今回の対象外：** 自動献立生成、医学的な栄養評価、アレルギー予防効果の保証、在庫管理。

## 訴求できる能力

ユーザーの希望と、実装すべき最小機能を区別し、スコープを限定した点に価値があります。フィードバックは少数の定性的意見であり、栄養改善・利用継続率・ダウンロード増加などの成果を実証したものではありません。
