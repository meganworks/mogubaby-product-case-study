# Quality Governance｜独立レビューが品質改善につながった事例

[ポートフォリオ](../../README.ja.md) ・ [English](../en/quality-management.md)

## 重要なのはデータの意味の整合性

他アプリからのインポートによって取得できる「最初に食べた日」と、アプリ内の記録から確実に把握できる「最後に食べた日」は同一ではありません。初期実装では、その区別が曖昧になる境界ケースが存在しました。

## レビューから是正まで

1. **別AIによるレビュー：** 初回摂取日を最終摂取日として誤認するリスクを指摘。
2. **要件の再定義：** 最終摂取日の根拠となる記録を明確化。
3. **修正：** Claude Codeが算出ロジックと曖昧データの表示条件を調整。
4. **回帰確認：** インポートと通常記録の混在、未来日付、並び替え等のテストを拡充。
5. **公開判断：** 技術レビュー後も人間による実機確認・最終承認を維持。

共有画像で長い食材名がはみ出す表示問題についても、レビューから修正・確認へつなげました。

## 検証範囲

特定のリリース候補に対して、GitHub Actions上で**88/88項目合格**という記録があります。ただし、全環境・全操作の品質保証を意味せず、レビュー担当AIがテストを独立実行したという意味でもありません。
